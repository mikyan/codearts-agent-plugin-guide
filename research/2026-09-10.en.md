## Security review

### Seven PM Skills

Each pinned candidate directory contains only `SKILL.md`: no dependency manifest, lockfile, lifecycle script, binary, downloader, telemetry, or local resource. Installation sparse-checks out the pinned commit and copies one directory into native `.codeartsdoer/skills/<name>`. Its vendor clone is independently removable and the user root `package.json` stays unchanged.

`draft-nda` and `privacy-policy` are legal/compliance drafting capabilities. Tests used fictional entities and synthetic facts, required explicit not-legal-advice, UNKNOWN, and legal-review markers, and failed any output that invented deadlines, controls, or legal conclusions.

### Three Dazbo security stops

- `deploy-skills-in-antigravity`: its core flow runs unpinned `npx skills`, writes `~/.agents/skills` and `~/.gemini/config/skills.json`, and its Windows relocation loops over every source Skill, deletes same-named targets, and moves every directory. The representative capability could not be bounded to one auditable candidate with exact rollback, so execution stopped before installation.
- `install-gemini-code-review-action`: it downloads workflow/TOML files from floating `main` URLs, checks authenticated GitHub CLI state, handles `GEMINI_API_KEY`, writes workflows, and asks to commit and push remotely. No authorized isolated GitHub repository or credential boundary was provided, so execution stopped before installation.
- `secrets-with-git-crypt`: upstream explicitly requires a Unix-like environment and `git-crypt`. Its script may run `sudo apt-get`, initialize Git filters, modify `.gitattributes`/`.gitignore`, copy secrets, and export or unlock an external key. This host is Windows and no authorized test key or Unix environment was in scope, so execution stopped before installation.
