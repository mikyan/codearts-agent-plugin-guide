## Batch result

This batch advanced ten previously uncovered Skills from the latest `sickn33/agentic-awesome-skills` release, `v17.8.4`, pinned to commit `5cebd344a13123d16e0ea453d56bb67984c493cf`. Nine candidates were independently installed in project A, a fresh project B, and user scope without a same-named project override. ## License and security review

- Agentic Awesome code and tooling are MIT; original non-code content is CC BY 4.0. Each selected mirror frontmatter declares MIT and links its original license.
- Every selected directory contained exactly one `SKILL.md`, with no manifest, lockfile, install/postinstall hook, binary, downloader, or telemetry code. Installation copied pinned files only; no command from a Skill body was executed.
- The complete `geo-prospect` workflow persists contact and commercial data under `~/.geo-prospects`. This run denied file, network, and command permissions and tested the read-only pipeline calculation with synthetic records only.
- The complete `career-ops` runtime can scan job portals and process resumes and applications. The mirrored package is explicitly docs-only; this run read no personal profile, visited no portal, sent no message, and submitted no application.
- `geo-report-pdf` documents macOS-only Pandoc and Chrome paths, while the docs-only mirror omits its templates and CSS. This host also had no Pandoc or Chrome command, so no generation command ran.
- The `interview-me` Loading Constraints explicitly forbid CI, scheduled runs, and autonomous loops. This task is scheduled automation, so it was neither installed nor invoked.

## Installation, discovery, and rollback method

Each executed candidate was copied from the pinned read-only source into a scope-specific `vendor/agentic-awesome-<name>` directory, then copied in full to CodeArts' native `skills/<name>` directory. No npm command or command from an upstream Skill body ran, and the user-root `package.json`, `codearts_cli.json`, persistent permissions, and credentials were untouched.

Each scope first ran real `codearts debug skill`. Parsed JSON had to contain exactly one match for both the candidate name and the absolute `SKILL.md` path. A candidate-specific `codearts run -m mimo/mimo-v2.5 --format json` invocation followed. After removing the exact Skill and vendor directories, another diagnostic required zero matches for the former `name + location`.
