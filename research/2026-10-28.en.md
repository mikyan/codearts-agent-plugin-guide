# 2026-10-28: Ten CodeArts checks from Agentic Awesome v20.1.0

[简体中文](2026-10-28.md)

## Summary

This batch advanced ten previously uncovered `SKILL.md` candidates. Every candidate was independently installed from a pinned Agentic Awesome `v20.1.0` checkout into project A, a fresh project B, and a user-scope consumer without a same-named project override. All 30 installed trees matched their candidate-specific source manifests, and all 30 `codearts debug skill` checks uniquely resolved the expected absolute path.

All 30 real `codearts run -m mimo/mimo-v2.5 --format json` candidate calls received upstream `400 Unsupported model mimo-v2.5` before any Skill or other tool event. A separate empty-project probe first received `Network request blocked` for the same MiMo chat-completions address; the formal batch assertion uses only the consistent 400 events in the 30 candidate JSONL files. CodeArts still returned process exit code 0, so neither a zero exit code nor diagnostic discovery is runtime-load evidence.

The batch passed 30/30 installations, 30/30 exact discoveries, 0/30 runtime loads and core calls, 0/20 second-environment and user-scope end-to-end checks, and 30/30 exact rollbacks. All ten results are **Untested (environment blocked)**, not incompatibility findings. No formal guide or guide-index row was added.

Each candidate independently followed this process:

1. Copy the candidate from the pinned checkout into a scope-specific `vendor/agentic-awesome-<name>/skills/<name>`, then copy it into native `.codeartsdoer/skills/<name>` without preserving the upstream `skills/` parent hierarchy.
2. Give project A and fresh project B separate `.codeartsdoer` roots. Use `C:\Users\AI_BA\.codeartsdoer\skills\<name>` and an isolated user vendor for user scope; the consumer has no same-name project override.
3. Recompute relative paths, byte counts, and SHA-256 for each install and require an exact match to that candidate's source manifest. Stop on any pre-existing same-name Skill or vendor.
4. Run `codearts debug skill` and require exactly one name/location match at the expected absolute `SKILL.md` path.
5. Run a candidate-specific safe-stop prompt through real `codearts run -m mimo/mimo-v2.5 --format json`. Passing requires a completed `skill` event from the intended directory plus a candidate-specific observable result; prose, files, or exit code 0 are insufficient.
6. Validate absolute targets before deleting only that candidate's Skill/vendor, then rerun diagnostics and require zero matches for the former path.

## Candidate-specific representative calls

- `curlshot`: public/private URL boundary, confidential HTML upload consent, non-overwriting output, response type, quota, and cost.
- `aident-loadout`: live schema, Vault connection, metered preflight, acknowledgement, and external-side-effect stop gates.
- `outreachgenie-list-audit`: five read-only capture tools, pagination completeness, prompt-injection data boundary, and offline-report limits.
- `krexa`: decode reuse, research/test limits, paper/live distinction, qualifying evidence, wallet approval, and pause semantics.
- `project-memory-log`: when to skip initialization, competing records, reuse before create, historical evidence, and two-record closure.
- `solidping`: read-only diagnosis, explicit confirmation before check writes, bounded retries, credentials, and no unmeasured uptime claim.
- `pangolinfo-amazon-data-research`: marketplace, read-only queries, retrieval-time provenance, pagination, and Amazon-data limits.
- `apify-linkedin-jobs-scraper`: inputs, dataset privacy, cost estimate, explicit approval, bounded runs, and no job applications.
