# 2026-10-23: Ten Agentic Awesome v19.13.0 CodeArts validations

[中文](2026-10-23.md)

## Conclusion

This batch advanced ten previously uncovered `SKILL.md` candidates. All 30 pinned installations across project A, fresh project B, and a user consumer without a project override were uniquely discovered by the real CodeArts CLI at the expected absolute paths. Every representative invocation then received `400 Unsupported model mimo-v2.5` during the model request and emitted no Skill or other tool event, so loading, core behavior, and end-to-end reproduction did not pass. All 30 exact rollbacks and post-removal diagnostics passed.

Every candidate is **Untested (environment blocked)**, not rejected as incompatible. No formal guide or guide-index row was created.

Every candidate independently followed this process:

1. In project A, fresh project B, and the user consumer, run `git clone --depth 1 --filter=blob:none --sparse --branch v19.13.0`, set sparse checkout to `skills/<name>`, and verify the full commit.
2. Project targets were `<project>/.codeartsdoer/skills/<name>` with vendor `<project>/.codeartsdoer/vendor/agentic-awesome-<name>`. User targets were the matching paths under `~/.codeartsdoer`. Any same-name collision stopped the run.
3. Run `codearts debug skill` and require one exact match for both candidate name and absolute `SKILL.md` path.
4. Start a candidate-specific representative call with real `codearts run -m mimo/mimo-v2.5 --format json`. The temporary permission fixture denied shell, file writes/reads, browser, network, and external-directory tools. Process-only non-secret placeholder AK/SK values were never persisted.
5. Before removal, revalidate that both targets were under the exact installation root. Remove only the candidate Skill and vendor, then require zero old-path matches from post-removal `codearts debug skill`.

## Environment-blocker evidence

- `codearts models` still lists `mimo/mimo-v2.5`, `mimo/mimo-v2.5-pro`, `huaweicloud-maas/GLM-5.1`, and `GLM-5.2`.
- All 30 candidate calls to `mimo/mimo-v2.5` returned the same upstream `400`: `Unsupported model mimo-v2.5`. The CodeArts process still exited 0, so this batch treats the JSON error body and zero tool events—not the exit code—as the failure assertion.
- A separate `mimo/mimo-v2.5-pro` probe also returned `400 Unsupported model mimo-v2.5-pro`.
- A separate `huaweicloud-maas/GLM-5.2` probe with non-secret placeholders returned `401 Incorrect IAM authentication information`. The automation process has no real `CODEARTS_CLI_AK` / `CODEARTS_CLI_SK`, so it cannot switch to Huawei Cloud MaaS for these calls.
- Every error occurred before any Skill event. Candidate instructions were never invoked, so `Works`, `Partial`, and formal guides are all disallowed.
