- Windows 11 Pro Build 26200; PowerShell 7.6.5; Git 2.53.0.windows.2; Node 24.14.1; npm 11.11.0.
- Real CodeArts CLI 26.8.1 at `%USERPROFILE%\.codeartsdoer\installers\codearts.cmd`. Commands attempted the previously verified `mimo/mimo-v2.5`, but this run could not re-confirm the model inventory without credentials.
- Environment-presence checks were `CODEARTS_CLI_AK=False` and `CODEARTS_CLI_SK=False`. No credential was read, printed, copied, or fabricated.
- The [official CodeArts CLI Skills documentation](https://support.huaweicloud.com/intl/en-us/usermanual-cli/codeartsagent_cli_0019.html), updated 2026-07-27, documents project `.codeartsdoer/skills/<name>`, user `~/.codeartsdoer/skills/<name>`, and project priority. Tests used these native directories without preserving deep upstream parent paths.
- Each executed candidate used `.tmp/verification/2026-08-21/scopes/<slug>/project-a`, a fresh `project-b`, and a `user-consumer` with no project override. User targets were `~/.codeartsdoer/skills/<slug>`.
- Every scope checked for same-name collisions, copied the complete pinned candidate bundle, ran `codearts debug skill` and a candidate-specific `codearts run -m mimo/mimo-v2.5 <prompt>`, removed the exact candidate directory, and ran diagnostics again.
- Every discovery and core command printed the authentication error saying `CODEARTS_CLI_AK/CODEARTS_CLI_SK` were unset. CLI 26.8.1 still returned exit code `0`, so this run uses the error text as the failure assertion and never treats exit zero as a successful load.
