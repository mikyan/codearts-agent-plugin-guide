## 安全审查

十个固定候选目录都只包含一个 `SKILL.md`，没有 package manifest、锁文件、install/postinstall、脚本、二进制、下载器、凭据读取或遥测。安装仅 sparse clone 固定 Commit 到独立 vendor，再把准确 Skill 目录复制到 CodeArts 原生位置；没有执行上游验证器、代码或生成脚本。

核心调用使用完整合成输入，拒绝 Shell、外部读取、浏览和外部目录访问。`dummy-dataset` 只写受约束 CSV，不执行生成代码；访谈内容完全合成，不含真实个人资料。

### 非交互写权限反证与最小适配

第一次探索性 `create-prd` 调用使用用户持久权限（`edit`/`write = ask`）和 `--auto`，Write 仍被自动拒绝，随后出现额外 Bash/Read 尝试。这条调用不计入最终 30 个范围。

按仓库兼容性 Skill 的最小适配梯，最终流程为每个工作目录创建独立 `KERNEL_DATA_DIR/storage/permission/global.json`：只允许 `edit` 与 `write`，明确拒绝 Bash、Read、WebFetch、WebSearch、外部目录和 dotfile；直接调用真实 CodeArts 26.8.1 `codearts.exe`，并复用官方启动器的进程环境。用户持久 `permission/global.json` 未修改。这是验证夹具适配，不是候选适配器，所以通过项结论仍为 Works。

## 安装、调用与回滚方法

每个候选分别使用以下三组目标：

- 项目 A：`.tmp/verification/2026-09-09-pm6b/runs/<name>-a/.codeartsdoer/skills/<name>` 与独立 vendor。
- 全新项目 B：`.tmp/verification/2026-09-09-pm6b/runs/<name>-b/.codeartsdoer/skills/<name>` 与独立 vendor。
- 个人级：`C:/Users/AI_BA/.codeartsdoer/skills/<name>` 与 `C:/Users/AI_BA/.codeartsdoer/vendor/pm-skills-<name>`；调用工作目录没有项目级同名 Skill。

每个范围均先运行真实 `codearts debug skill`，要求输出包含准确绝对目标；再运行 `codearts run -m mimo/mimo-v2.5 --auto --format json <候选专用提示词>`，要求一次完成的目标 Skill 事件从该目录解析，再要求一次完成的 Write 和磁盘内容断言。每次结束后删除准确 Skill、vendor、合成产物与临时权限，并再次运行 `codearts debug skill` 确认原路径不再出现。
