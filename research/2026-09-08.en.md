## Environment and isolation

- CodeArts CLI 26.8.1 at `%USERPROFILE%\.codeartsdoer\installers\codearts.cmd`.
- Windows 11 build 26200; PowerShell 7.6.5; Git 2.53.0.windows.2; Node 24.14.1; npm 11.11.0.
- Model: `mimo/mimo-v2.5`. The automation inherited neither `CODEARTS_CLI_AK` nor `CODEARTS_CLI_SK`. Child verification processes used non-secret, non-persisted placeholders only to pass the custom-provider preflight; existing provider configuration still authenticated the model. No key was printed, copied, hashed, or modified.
- Project A/B lived under `.tmp/verification/2026-09-08-pm5/runs/<name>-a` and `<name>-b`. The `<name>-user` consumer had no same-named project override.
- Project targets were `<project>/.codeartsdoer/skills/<name>` and `<project>/.codeartsdoer/vendor/pm-skills-<name>`. User targets were `~/.codeartsdoer/skills/<name>` and `~/.codeartsdoer/vendor/pm-skills-<name>`.
- Each scope used its own sparse checkout from the pinned source and copied only the candidate directory. `codearts debug skill` ran before a candidate-specific `codearts run -m mimo/mimo-v2.5 --format json`. Each invocation had a 90-second hard limit and no retry.

## Security review

Each of the ten target directories contained one ordinary mode-`100644` text `SKILL.md`. There were no manifests, lockfiles, lifecycle scripts, executable scripts, binaries, downloaders, MCP servers, hooks, commands, telemetry, or credential reads. The representative prompts prohibited network access and file writes.

All user skill and vendor targets were absent before installation. The flow did not run upstream `validate_plugins.py`, tests, or unrelated plugin content; it did not use `--auto` or modify the user-root `package.json`, `codearts_cli.json`, or credentials.
