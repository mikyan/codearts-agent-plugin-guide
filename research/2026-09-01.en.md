[中文](2026-09-01.md)

No formal guide is published.

## Upstream, discovery sources, and safety review

- Candidates came from the [GitHub Agent Skills topic](https://github.com/topics/agent-skills), the popular [mattpocock/skills](https://github.com/mattpocock/skills), and the recently active [derailed-dash/dazbo-agent-skills](https://github.com/derailed-dash/dazbo-agent-skills). On 2026-09-01 the Matt page showed 20.6k forks and 440 issues; the latest cross-checkable 2026-08-31 snapshot recorded 242,450 stars. Dazbo showed 22 stars, 2 forks, and 52 commits.
- Matt was pinned at commit `6654f6b60cd9d5be8b54c6fafe44346dabeb3b76`, release `v1.2.3`, MIT. Dazbo was pinned at commit `1dcbfd708fc117acef9f2dc17fa2d3ecd4a52d5a`, no release, MIT; the pinned commit date was 2026-08-14.
- Each installed candidate copied only its pinned Skill directory and local resources to `.codeartsdoer/skills/<name>`. Deep parents such as `skills/in-progress` and `skills/misc` were not reproduced at the target. No upstream root installer, telemetry, or credential flow ran.
- `migrate-to-shoehorn` supplied an unversioned command. After npm metadata review, this run pinned `@total-typescript/shoehorn@0.1.2` and used `npm install --ignore-scripts --no-audit --no-fund`. `setup-ts-deep-modules` pinned `dependency-cruiser@18.2.0` and `typescript@5.9.2` with lifecycle scripts disabled, and copied its local `dependency-cruiser.config.cjs` plus the `codebase-design` dependency.
- The `git-guardrails-claude-code` Bash script depends on `jq`/`grep` and Claude Code `PreToolUse`. The run did not execute it or create `.claude` configuration; it only verified content loading and that this is not a native CodeArts Hook.
- `claude-handoff` sends a redacted summary to a new external `claude --bg` process. `implement-spec` creates a draft PR, branches/worktrees, and implementer, merger, and reviewer agents. Those side effects exceed the isolated read/local-write boundary, so neither candidate was installed or invoked.
- `create-md-from-browsermcp-snapshot` strictly requires BrowserMCP and `browser_snapshot`. That MCP was unavailable. Its Python parser was fully reviewed, but the upstream prerequisite guard prohibited bypassing the missing MCP by running it directly.
- Every template and sample bundled with `maintaining-core-documentation` was reviewed. Samples include fake Bearer tokens and local `curl` examples; none were executed or copied. The candidate could only update one testing document from isolated `CHANGE.md` facts.

## Per-candidate core evidence

1. **`claude-handoff` — Untested:** its representative capability runs `claude --bg --name ...` and sends the current conversation summary as a new-agent prompt rather than creating a local artifact. No external-agent task or matching sensitive-data boundary was authorized, so execution stopped before installation.
2. **`git-guardrails-claude-code` — Partial:** all scopes completed `Skill "git-guardrails-claude-code"` from exact paths and correctly listed `git push`, `git reset --hard`, `git clean -f/-fd`, `git branch -D`, `git checkout .`, and `git restore .`. All three final texts said Claude Code `PreToolUse` is not a CodeArts Hook. `.claude` remained absent, so content comprehension was not misreported as Hook operation.
3. **`implement-spec` — Untested:** the core flow requires a draft PR, remote issue/ticket closing links, concurrent agents, independent worktree merges, and a ready-for-review state change. Safety review distinguished utility from risk; no fake PR or simulated agent was substituted.
4. **`migrate-to-shoehorn` — Partial:** every scope discovered and loaded the main Skill with the pinned dependency present. Project A and user text described the correct `fromPartial` change, but `edit:error`/`write:error` showed permission rejection and disk retained `as User`. Project B timed out after one `edit:error`. No scope ran a post-migration test.
5. **`scaffold-exercises` — Partial:** every scope completed the main Skill and produced non-empty `exercises/01-evidence/01.01-observable-events/explainer/readme.md`. Projects A/B explicitly acknowledged that repository-specific `pnpm ai-hero-cli internal lint` and the commit were omitted; user scope had the artifact but timed out. This proves the scaffolding sub-capability, not upstream's completion criteria.
6. **`setup-ts-deep-modules` — Partial:** every scope completed `setup-ts-deep-modules` and nested `codebase-design` Skill events. Project A left only `.dependency-cruiser.cjs`; project B/user stopped during environment detection or before writes. No scope combined the example package, documentation pointer, `lint:boundaries`, and real pass/fail/pass evidence. All three timed out.
7. **`convert-to-devto` — Partial:** every scope completed the main Skill but timed out after `write:error`; none created `devto.md`, while `source.md` remained. Title retention, highlight removal, language fence, and nested fence behavior could not be accepted without an artifact.
8. **`maintaining-core-documentation` — Partial:** every scope loaded the main Skill, then recorded `edit:error`/`write:error` or timed out. Each `docs/testing.md` retained stale `yarn test`/Jest text instead of fixed `npm test` and `node:test`; protected README and TODO files remained unchanged.
9. **`organise-agent-skills` — Partial:** every scope loaded the main Skill and left fixtures unchanged. User scope correctly identified `new-skill`, orphan `legacy-skill`, and `//core-skill`, presented baseline/proposed metrics, and stopped for confirmation. Projects A/B timed out before final audit tables. More importantly, its state model targets Gemini/Antigravity `skills.json`, not CodeArts Skill management.
10. **`create-md-from-browsermcp-snapshot` — Partial:** every scope completed the main Skill and stopped after reporting unavailable BrowserMCP/`browser_snapshot`. It did not run the parser, create `output.md`, or change input. The prerequisite guard works, but webpage capture and Markdown conversion remain unproved.
