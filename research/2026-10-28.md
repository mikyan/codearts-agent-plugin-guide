# 2026-10-28：Agentic Awesome v20.1.0 十项 CodeArts 验证

[English](2026-10-28.en.md)

## 结论摘要

本批实际推进 10 个此前未覆盖的 `SKILL.md` 候选。每个候选都从固定的 Agentic Awesome `v20.1.0` checkout 独立安装到项目 A、全新项目 B 和无项目级同名覆盖的个人级 consumer；30/30 份安装内容与各自 source manifest 一致，30/30 次 `codearts debug skill` 都从预期绝对路径唯一发现候选。

真实 `codearts run -m mimo/mimo-v2.5 --format json` 的 30 次候选调用均在任何 Skill 或其他工具事件之前收到上游 `400 Unsupported model mimo-v2.5`。独立的空项目探针还曾收到一次到同一 MiMo chat-completions 地址的 `Network request blocked`；正式批次的失败断言只使用 30 份候选 JSONL 中一致的 400 事件。CodeArts 对这些错误仍返回退出码 0，因此不能用退出码或诊断发现代替运行时加载证据。

本批安装 30/30、精确发现 30/30、运行时加载与核心调用 0/30、第二环境和个人级端到端 0/20、精确回滚 30/30。十项均为 **Untested（环境阻塞）**，不是不兼容结论；没有创建正式指南或新增指南索引。

## 环境与隔离方法

| 项目 | 值 |
| --- | --- |
| CodeArts CLI | 26.8.1，真实二进制 `C:\Users\AI_BA\.codeartsdoer\installers\bin\codearts.exe` |
| 系统 | Windows 11 专业版 25H2，Build 26200.9711 |
| Shell / 工具 | PowerShell 7.6.6；Git 2.53.0.windows.2；Node 24.14.1；npm 11.11.0 |
| 配置模型 | `mimo/mimo-v2.5`；正式批次端点返回不支持 |
| 固定版本 | Agentic Awesome `v20.1.0` / `ed953dd2928104238cd0b71d0789137e77e90cae` |

每个候选独立执行：

1. 从 `v20.1.0` 固定 checkout 复制候选目录到本作用域独立 `vendor/agentic-awesome-<name>/skills/<name>`，再复制到 CodeArts 原生 `.codeartsdoer/skills/<name>`；不携带上游 `skills/` 父层级。
2. 项目 A 和全新项目 B 使用各自 `.codeartsdoer`。个人级使用 `C:\Users\AI_BA\.codeartsdoer\skills\<name>` 与独立 vendor；consumer 没有同名项目覆盖。
3. 对每份安装重新计算相对路径、字节数与 SHA-256，要求与候选自己的 source manifest 完全一致；任何同名 Skill/vendor 预存在即停止。
4. 运行 `codearts debug skill`，要求候选名和预期 `SKILL.md` 绝对路径唯一精确匹配。
5. 使用候选专属的安全停止提示词运行真实 `codearts run -m mimo/mimo-v2.5 --format json`。通过必须包含来自预期目录的 completed `skill` 事件和候选特定可观察结果；自然语言、文件存在或退出码 0 均不算。
6. 删除前确认绝对路径位于精确安装根，只删除本候选 Skill/vendor；再运行诊断，要求原路径零匹配。

## 环境阻塞证据

- 自动化进程没有真实 `CODEARTS_CLI_AK` / `CODEARTS_CLI_SK`。进程级非秘密占位值仅用于到达既有 MiMo 配置，没有写入磁盘或文档。
- 30/30 次候选调用各得到一个 `type:error`，正文含 `400 Unsupported model mimo-v2.5`；30/30 均无 `tool` 字段、Skill call ID、MCP、Hook 或其他工具事件。
- CodeArts 对这些错误返回退出码 0，因此用错误正文和零工具事件断言失败。
- 独立空项目探针曾先得到 `Network request blocked`；正式批次随后稳定到达端点并得到 400。两种错误都发生在候选加载前，均不能评价候选语义、脚本、MCP、Windows 核心行为或个人级核心行为。

## 候选级代表调用

- `curlshot`：检查公开/私网 URL、机密 HTML 上传同意、不覆盖输出、响应类型、额度与成本边界。
- `aident-loadout`：检查 live schema、Vault connection、计费 preflight、acknowledgement 与外部副作用停止门槛。
- `outreachgenie-list-audit`：检查五个只读 capture 工具、分页完整性、prompt injection 数据边界和离线报告限制。
- `krexa`：检查 decode 复用、研究/测试额度、paper/live 区分、合格证据、钱包批准与 pause 语义。
- `project-memory-log`：检查何时跳过初始化、竞争记录处理、先复用后创建、历史证据标注和双记录收尾。
- `solidping`：检查只读诊断、创建/修改监控的明确确认、有界重试、凭据和无实测 uptime 声明。
- `pangolinfo-amazon-data-research`：检查 marketplace、只读查询、检索时间/来源、分页和 Amazon 数据限制。
- `apify-linkedin-jobs-scraper`：检查输入、数据集隐私、费用估算、明确批准、运行上限和禁止代投。
- `deed-page`：检查公开披露、secret scan、build-output 范围、token 私密处理、重试与不可逆删除门槛。
- `taasky`：检查 origin、room token、对方内容视为数据、用户 limits、时区和人类确认门槛。

这些提示词均禁止候选特有的网络、账户、付费、写入或外部副作用。30 次调用都在 Skill 事件前失败，所以没有产生候选语义证据。

## 回滚与正式指南决定

- 30/30 个候选 Skill 目标和 30/30 个独立 vendor 目标已精确删除；删除后诊断对原绝对路径均为零匹配。
- 用户根 `package.json`、`codearts_cli.json` 和持久权限文件 SHA-256 前后分别保持 `589A2F93D6B401FCCE4EDED58C4C477C3891C3B580796862C58ACB4E5D73A4E7`、`6F08A23430F657E3CBF75ABDCF1CB7A08FE88504F6FDC51BA31B6530386E2E23`、`AC7831CD9D9FB18023BFD6C7778E71FF4A0DBCADAE60948189FBB0ECFDE2F447`；个人级候选残留为零。
- `.tmp/v1028` 只保留 Git 忽略的本地证据，不进入提交。
- 没有候选同时满足安装、运行时加载、核心调用、全新环境复现和回滚五项门槛。因此不创建 `guides/` 内容，也不修改正式指南表。恢复可用模型后必须从固定 commit 重做候选专属调用；本批发现和回滚不能替代后续核心证据。
