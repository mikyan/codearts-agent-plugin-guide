## Summary

This batch advanced ten previously uncovered candidates: `access-matrix`, `agentic-test-audit`, `ai-agent-evaluation-benchmarking`, `ai-code-generation-guardrails`, `ai-prompt-regression-testing`, `api-contract-testing`, `audit-log`, `data-privacy-controls`, `five-axis-code-review`, and `mcp-dependency-drift-audit`. The pinned source was Agentic Awesome `v20.6.0` / `739c841480587361c3cb2047f5b34cdca69a0623`.

Every candidate independently received source-hash verification, unique CodeArts discovery, a real `codearts run`, exact removal, and post-removal discovery in project A, a fresh project B, and user scope: 30/30 installs, 30/30 discoveries, and 30/30 rollbacks passed. However, all 30 `mimo/mimo-v2.5` calls returned `400 Unsupported model mimo-v2.5` before any `skill` or other tool event. An independent `mimo/mimo-v2.5-pro` probe was blocked by network policy before any tool event. All ten results are therefore **Untested (environment blocked)**, not incompatibility findings. No guide or guide-index row was added.

Official documentation places project skills under `<project>/.codeartsdoer/skills`, user skills under `~/.codeartsdoer/skills`, and states that project scope wins for same-name skills. This batch created no same-name conflict; user calls ran from independent workspaces with no project override.

Each candidate independently followed this process:

1. Project A: copy the pinned directory to `.tmp/verification/2026-11-09-agent-skills/<candidate>-a/.codeartsdoer/skills/<candidate>`, verify the manifest, run discovery and the candidate-specific call, remove the exact target, and check discovery again.
2. Project B: repeat from a new empty workspace without reusing project A installation, invocation, or rollback evidence.
3. User scope: after confirming no collision, copy to `C:\Users\AI_BA\.codeartsdoer\skills\<candidate>`, then repeat discovery, invocation, and exact rollback from an independent consumer directory.

User-scope validation did not modify the user-root `package.json`, `codearts_cli.json`, or persistent permission file. No deep upstream parent path was carried into the CodeArts target.
