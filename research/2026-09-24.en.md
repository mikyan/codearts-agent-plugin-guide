## Batch conclusion

This batch advanced ten previously uncovered `SKILL.md` candidates pinned to `sickn33/agentic-awesome-skills` release `v18.3.0` and commit `dbe7f3652dda7a24a15abc0bfbb5d4868c4cf1b1`. Six were new in the release; four were uncovered general-purpose Skills from the same immutable snapshot. Every candidate received its own safety review, project A installation, fresh project B reproduction, user-scope installation without a project override, real CodeArts discovery and invocation, and exact rollback.

All 30 installed states were discovered by real `codearts debug skill` at the exact absolute path; all 30 `codearts run` calls exited 0; and all 30 installed targets were precisely removed and absent from post-removal discovery. No candidate passed both the semantic consistency and attributable-call gates. Eight produced factual errors, unsupported additions, or cross-scope contradictions; `api-security-best-practices` loaded twice in user scope; and `async-python-patterns` followed different Skill/resource call paths across scopes and repeated the Skill in project A. All ten results are therefore **Partial**. No formal guide or guide-index entry was added.

## License and safety review

- Eight candidate directories contain only `SKILL.md`; `async-python-patterns` and `auth-implementation-patterns` each add one Markdown playbook. Every pinned file was reviewed and included in a SHA-256 source manifest.
- The candidate directories contain no manifest, lockfile, install/preinstall/postinstall hook, executable script, binary, downloader, or candidate telemetry. No upstream repository npm script was run.
- Upstream code and tooling are MIT. Original non-code content defaults to CC BY 4.0 under `LICENSE-CONTENT`; the six new v18.3.0 candidates separately declare MIT in frontmatter. More specific third-party notices remain controlling.
- Chat and OneRoster tests used inline synthetic data only. API and authentication tests reviewed fictional routes without scans, tokens, or network access. DALI, EOL, and Marlin calls produced read-only plans and never touched hardware. ESL never contacted a retail system or sent a price update.
- Installation copied only the pinned directory into native CodeArts `.codeartsdoer/skills/<name>` plus a separately removable `vendor/agentic-awesome-<name>`. User-root `package.json`, `codearts_cli.json`, persistent permissions, and credentials were not modified.

## Installation, discovery, invocation, and rollback method

Each candidate independently followed this process; evidence was never shared across candidates:

1. Copy the pinned candidate to an isolated vendor directory and then to `.codeartsdoer/skills/<name>`; stop on any same-name collision.
2. Run real `codearts debug skill` and require exactly one matching name and absolute `SKILL.md` path.
3. Run a candidate-specific `codearts run -m mimo/mimo-v2.5 --format json` with complete synthetic input and explicit tool prohibitions.
4. Preserve target Skill and other tool events, call IDs, final text, and exit state from JSONL; manually check semantic assertions.
5. Repeat from zero in a second fresh project and again in user scope from a directory without a project override.
6. Before removal, prove that exact targets are children of the intended `.codeartsdoer` root. Remove only the exact Skill and vendor directories, rerun discovery, and compare user-file baseline hashes.

## Scope limitations

Results cover only Windows 11, CodeArts CLI 26.8.1, `mimo/mimo-v2.5`, the pinned commit, and the bounded synthetic workflows above. Linux/macOS, IDE/desktop clients, other models, real chats or education records, real APIs or identity systems, production retail systems, and physical DALI, alarm, or 3D-printer devices were not tested. Hardware and standards output is not a substitute for primary manuals, field measurements, or qualified professionals.
