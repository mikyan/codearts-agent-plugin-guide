## License and safety review

- Every candidate was pinned to the same immutable commit. Upstream code and tooling are MIT; original non-code content defaults to CC BY 4.0, with candidate-specific frontmatter and bundled notices taking precedence.
- `uxkin-research`, `equibles`, `url-to-markdown`, `kernel-prompt`, `skeleton-first`, and `changelog-entry` contain only `SKILL.md`. `what-could-break` adds an MIT notice; `business-email-template` adds one Markdown reference; `reverse-engineer-anything` adds five Markdown references; `tastegate` adds one Python script and five references/notices.
- No selected directory has a package manifest, lockfile, install/preinstall/postinstall script, candidate telemetry, or bundled binary. Copy installation runs no npm or pip lifecycle.
- `reverse-engineer-anything` documents floating `npx rea-agents@latest` commands, which were explicitly forbidden in this batch. `tastegate` recommends installing Playwright and Chromium on first use; no unpinned installation was run, and only the script's real missing-dependency behavior was tested. Neither received a guide.
- `equibles` did not inspect environment variables, API keys, or an account; `uxkin-research` did not connect UXKIN MCP. `url-to-markdown` accessed only public `https://md.replynodes.com/example.com`, treating returned content as untrusted data.
- Installations used native `.codeartsdoer/skills/<name>` plus isolated `vendor/agentic-awesome-<name>`. User-root `package.json`, `codearts_cli.json`, persistent permissions, and credentials were not changed.

## Install, discovery, invocation, and rollback method

For every main candidate, the pinned directory was copied to a scope-local vendor and then to native Skills. `codearts debug skill` had to show exactly one matching `name + SKILL.md` absolute path. A candidate-specific `codearts run -m mimo/mimo-v2.5 --format json` preserved JSONL, call IDs, and final text for manual semantic review. The process was repeated from zero in project B and user scope. Only the exact Skill and vendor targets were removed, followed by a real post-removal discovery check.

The four initial passes then followed the proposed guide flow: sparse-clone GitHub tag `v19.4.0` in each scope, verify the full commit, copy to native Skills, invoke, and roll back. `changelog-entry` was withdrawn because publication project B violated its output-only boundary. `what-could-break` received one further exact-layout check: the first attempt launched from the smoke subdirectory and produced `skill:error` in project A/B, so that entire set was excluded; after launching at the project root while limiting inspection to the subdirectory, project A, project B, and user scope all passed.

Before the clean main run, a user-scoped `reverse-engineer-anything` residue from the interrupted 2026-10-10 run was found. All six file paths, byte counts, SHA-256 values, and timestamps matched the old automation manifest. The two exact Skill/vendor directories were moved to automation quarantine before a new evidence root was used. The contaminated project A/B attempt was excluded completely.
