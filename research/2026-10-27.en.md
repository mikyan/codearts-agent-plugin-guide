## Summary

This batch advanced ten previously uncovered `SKILL.md` candidates. Each candidate was independently installed in project A, a fresh project B, and a user-scope consumer with no same-named project override. All 30 installations matched their pinned source file-by-file by SHA-256, and all 30 `codearts debug skill` runs discovered the candidate exactly once at the expected absolute path.

The same-day model probe and all 30 real `codearts run -m mimo/mimo-v2.5 --format json` attempts received upstream `400 Unsupported model mimo-v2.5` before any Skill or other tool event. CodeArts still exited 0, so this batch uses the JSON error body and zero tool events as the failure assertion; discovery success is not reported as runtime loading. All 30 precise rollbacks and post-removal diagnostics passed.

Every candidate is **Untested (environment blocked)**, not incompatible. This batch created no formal guide and added no guide-index row.

Across the five gates: installation was 30/30, exact discovery 30/30, runtime loading and core invocation 0/30, fresh-project and user-scope end-to-end reproduction 0/20, and rollback 30/30.

Each candidate independently followed these steps:

1. Copy the candidate directory from the locally pinned checkout into an isolated vendor, then copy it into CodeArts' native `.codeartsdoer/skills/<name>` path. The upstream `skills/` parent hierarchy was not carried into the native target.
2. Project A and the fresh project B each used their own `.codeartsdoer`. User scope used `C:\Users\AI_BA\.codeartsdoer\skills\<name>` plus independently removable `C:\Users\AI_BA\.codeartsdoer\vendor\agentic-awesome-<name>`, from a consumer with no same-named project override.
3. Recompute relative paths, byte counts, and SHA-256 for every installation and require an exact match to that candidate's own pinned source manifest. Stop on any pre-existing same-name Skill or vendor collision.
4. Run `codearts debug skill` and require exactly one match for the candidate name and absolute `SKILL.md` path.
5. Run real `codearts run -m mimo/mimo-v2.5 --format json` with a candidate-specific prompt. Passing requires a completed Skill event from the intended directory plus an observable result; natural-language text or process exit 0 alone never passes.
6. Before removal, verify that each absolute target is under its exact installation root. Remove only the candidate Skill and vendor, then rerun diagnostics and require zero matches for the old path.

## Environment-block evidence

- The automation process had no real `CODEARTS_CLI_AK` or `CODEARTS_CLI_SK`; `codearts models` therefore reported authentication failure. Process-only non-secret placeholders merely reached the already configured external MiMo endpoint and were never persisted.
- The independent model probe and all 30 candidate calls returned the same upstream error: `400 Unsupported model mimo-v2.5` from the MiMo chat-completions endpoint.
- CodeArts exited 0 for these errors. Every JSONL file contained exactly one `type:error` event, and all 30 contained no `tool` field, Skill call ID, MCP, Hook, or other tool event.
- The error happened before candidate content was invoked, so it cannot evaluate semantic correctness, scripts, external services, Windows runtime behavior, or user-scope core behavior. Placeholders are not credentials and cannot authorize switching to Huawei Cloud MaaS.

## Candidate-specific representative calls

- `us-watchlist-alerts`: use a synthetic AAPL stop request to check the three-upstream-Skill prerequisite, quote-delay and market-hours limits, local state, and no-trading boundary.
- `animated-github-profile`: design three SVGs for a fictional developer with theme switching, reduced motion, XML validation, unique IDs, cache-update order, and minimum Actions permissions.
- `launch-check`: without URL, owner, or browser authorization, check static scope, owner-only database gates, browser risk, redaction, and score limitations.
- `second-deposit-igaming`: without a player export or operator authority, check local privacy, field mapping, non-causal limits, responsible-gambling exclusion, and country-rule gates.
- `usage-engineer`: without log or session authorization, check long-log summarization, repeated-failure handling, map freshness, narrow reading, and the rule to report only measured tokens.
- `watch-igaming`: without media or dependencies, check secure temporary storage, bounded downloads, subtitle-first processing, scene sampling, timecode evidence, unobserved intervals, and retention.
- `shopify-firebase-app`: without version, account, credential, or cloud authority, check owner decisions, secrets, tenant isolation, tests, and resource inventory before scaffold and deploy.
- `design-token-contrast`: use a synthetic CSS token pair to check WCAG thresholds, checker extraction and no-overwrite workflow, and the boundary that token checks are not page certification.
- `unpaid-intern`: with the full kit absent, check immutable-kit review, the Markdown workspace, fact labels, restricted-data exclusions, and draft-only external-action stop rules.
- `goal-instruction-writer`: request a Goal for ten read-only text files with anchor, acceptance, verification, drift, budget, and terminal states, without executing that Goal.

All 30 prompts were blocked by the same model error before the Skill call, so they produced no candidate-semantic evidence.
