[English](2026-10-26.en.md)

## 结论摘要

本批实际推进 10 个此前未覆盖的 `SKILL.md` 候选。每个候选都在项目 A、全新项目 B 和无项目级同名覆盖的个人级 consumer 中独立安装；30/30 份安装内容与固定源文件逐文件 SHA-256 一致，30/30 次 `codearts debug skill` 都从预期绝对路径唯一发现候选。

30 次真实 `codearts run -m mimo/mimo-v2.5 --format json` 都在任何 Skill 或其他工具事件之前收到上游 `400 Unsupported model mimo-v2.5`。CodeArts 进程退出码仍为 0，因此本批以 JSON 错误正文与零工具事件为失败断言，不能把“发现成功”写成“加载成功”。30/30 次精确回滚与删除后诊断通过。

全部候选结论均为 **Untested（环境阻塞）**，不是对候选兼容性的否定。本批没有创建正式指南，也没有新增指南索引。

## 环境与隔离方法

| 项目 | 值 |
| --- | --- |
| CodeArts CLI | 26.8.1，真实二进制 `C:\Users\AI_BA\.codeartsdoer\installers\bin\codearts.exe` |
| 系统 | Windows 11 25H2，Build 26200 |
| Shell / 工具 | PowerShell 7.6.6；Git 2.53.0.windows.2；Node 24.14.1；npm 11.11.0 |
| 配置模型 | `mimo/mimo-v2.5`；真实端点当前返回不支持 |
| 固定版本 | Agentic Awesome `v20.0.0` / `6d4ea18320984083107f07ff69587fa355ee94c0` |

每个候选独立执行以下步骤：

1. 从已通过 tag/commit 校验的本地固定 checkout 复制候选目录到独立 vendor，再复制到 CodeArts 原生 `.codeartsdoer/skills/<name>`。没有携带上游 `skills/` 父目录层级到原生目标。
2. 项目 A、全新项目 B 分别使用其自己的 `.codeartsdoer`；个人级使用 `~/.codeartsdoer/skills/<name>` 与可单独删除的 `~/.codeartsdoer/vendor/agentic-awesome-<name>`，consumer 中没有同名项目覆盖。
3. 对每份安装重新计算相对路径、字节数与 SHA-256，要求与固定源 manifest 完全一致；同名 Skill 或 vendor 预存在时立即停止。
4. 运行 `codearts debug skill`，要求候选名与 `SKILL.md` 绝对路径唯一精确匹配。
5. 使用候选专属提示词运行真实 `codearts run -m mimo/mimo-v2.5 --format json`。断言必须包含来自预期目录的 completed Skill 事件和可观察结果；仅自然语言文本或退出码 0 不算通过。
6. 删除前核对目标绝对路径位于精确安装根内，只删除候选 Skill 与 vendor。随后再次运行诊断，要求旧路径零匹配。

- `codearts models` 仍列出 `mimo/mimo-v2.5`、`mimo/mimo-v2.5-pro`、`huaweicloud-maas/GLM-5.1` 和 `GLM-5.2`。

- CodeArts 为这些错误返回进程退出码 0；JSON 正文为 `type:error`，且没有 `skill`、MCP、Hook 或其他工具事件。
- 自动化进程没有真实 `CODEARTS_CLI_AK` / `CODEARTS_CLI_SK`，不能改用华为云 MaaS 模型。占位值不能变成凭据，也没有被持久化。
- 错误发生在候选内容调用之前，所以不能据此评价语义正确性、外部服务兼容性或 Windows 运行时兼容性。

## 候选级代表调用

- `product-design-harness`：审查仅有一个利益相关者意见、无用户研究的可逆帮助面板试点，要求三条 flow、证据等级、边界和下一人类决策。
- `a4a`：在没有 SDK、身份、relay 与收件人授权时，要求列出只读能力检查和停止边界。
- `cooper-email`：在没有账户、密钥、收件人与发送授权时，要求处理一次性秘密、幂等、有限等待与 OTP 边界。
- `faber-language`：在编译器缺失时，要求区分 `check` 与 `run` 并说明核心语法，不得声称代码已验证。
- `doomsday-escrow`：在 verifier 与链证据缺失时，要求列出固定源审查和独立验证字段，不得给真实 bounty 分类。
- `datawebot`：在 MCP、登录和消费授权缺失时，要求说明 discover-first、Job 授权、幂等重试和有限轮询。
- `footval-follow-matches-and-tables`：要求离线说明不同查询的工具选择、UTC 与新鲜度边界，不得编造比分。
- `footval-scout-and-rank-players`：把“意甲、左脚、中卫、23 岁以下、低于 3000 万欧元”转成精确筛选边界，不得命名球员。
- `footval-stats-and-transfer-news`：说明欧冠射手榜与 Galatasaray 传闻的参数及可靠性边界，不得编造榜单或转会。
- `footval-value-and-compare-players`：说明 FootVal 值、市场值、±5% fair 区间和估值因素，不得给真实球员估值。

上述 30 次提示词都在 Skill 调用前被同一模型错误阻断，没有产生候选语义证据。
