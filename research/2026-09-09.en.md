## Security review

Each pinned candidate directory contains one `SKILL.md` only: no package manifest, lockfile, install/postinstall, script, binary, downloader, credential access, or telemetry. Installation sparse-cloned the fixed commit into a dedicated vendor and copied the exact skill directory into native CodeArts placement. No upstream validator, code, or generated script was executed.

Core calls used complete synthetic inputs and denied shell, external reads, browsing, and external-directory access. `dummy-dataset` wrote a constrained CSV but executed no generated code. The interview was fully synthetic and held no real personal data.

### Non-interactive write counterevidence and minimal fixture

The first exploratory `create-prd` call used persistent user permissions (`edit`/`write = ask`) with `--auto`; Write was still auto-rejected, followed by extra Bash/Read attempts. That call is excluded from the final 30 scopes.

Following the repository compatibility skill's least-invasive ladder, each final workspace received an isolated `KERNEL_DATA_DIR/storage/permission/global.json`: Edit and Write allowed, while Bash, Read, WebFetch, WebSearch, external-directory access, and dotfile access were denied. The real 26.8.1 `codearts.exe` ran with the official launcher environment. Persistent user `permission/global.json` was unchanged. This is a test-fixture adaptation, not a candidate adapter, so successful skills remain Works.

## Installation, invocation, and rollback

Each candidate used three independent targets:

- Project A: `.tmp/verification/2026-09-09-pm6b/runs/<name>-a/.codeartsdoer/skills/<name>` plus its vendor.
- Fresh project B: `.tmp/verification/2026-09-09-pm6b/runs/<name>-b/.codeartsdoer/skills/<name>` plus its vendor.
- User: `C:/Users/AI_BA/.codeartsdoer/skills/<name>` and `C:/Users/AI_BA/.codeartsdoer/vendor/pm-skills-<name>`, invoked from a directory without a project override.

Every scope first ran real `codearts debug skill` and required the exact absolute target. It then ran `codearts run -m mimo/mimo-v2.5 --auto --format json <candidate prompt>`, requiring one completed target-skill event from that directory, one completed Write, and candidate-specific disk assertions. Each scope removed the exact skill, vendor, synthetic artifact, and temporary permissions; a second diagnostic excluded the former absolute path.
