## Compatibility findings

1. The upstream dependencies installed successfully in two independent project directories per project.
2. CodeArts did not scan project plugin entrypoints ending in `.mjs`. Equivalent `.js` wrappers loaded successfully.
3. With only the `.js` wrapper, `codearts debug skill` displayed the upstream skills added through the plugin's `config.skills.paths` hook.
4. A real `codearts run` session still reported those dynamically added skills as unavailable to its `skill` tool. The runtime tool contained only CodeArts system skills.
5. Copying the upstream skill directories to CodeArts' native project path, `.codeartsdoer/skills`, fixed runtime discovery. The plugin wrapper was retained for the upstream hooks and, for Ponytail, command registration.
6. The same adapted layout succeeded in the second independent project for each candidate.
7. Moving the complete project `.codeartsdoer` directory aside caused the third-party skills to disappear from discovery; restoring it restored the installation. This verified a project-local rollback boundary.

The adapter is therefore necessary for CodeArts CLI 26.8.1. It consists of a `.js` plugin entrypoint plus a project-local copy of the upstream skill directories.
