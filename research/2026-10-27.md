# 2026-10-27：Agentic Awesome v20.0.0 十项 CodeArts 验证

[English](2026-10-27.en.md)

## 结论摘要

本批实际推进 10 个此前未覆盖的 `SKILL.md` 候选。每个候选都在项目 A、全新项目 B 和无项目级同名覆盖的个人级 consumer 中独立安装；30/30 份安装内容与固定源文件逐文件 SHA-256 一致，30/30 次 `codearts debug skill` 都从预期绝对路径唯一发现候选。

当天模型探针和 30 次真实 `codearts run -m mimo/mimo-v2.5 --format json` 均在任何 Skill 或其他工具事件之前收到上游 `400 Unsupported model mimo-v2.5`。CodeArts 进程退出码仍为 0，因此本批以 JSON 错误正文与零工具事件为失败断言，不能把“发现成功”写成“加载成功”。30/30 次精确回滚与删除后诊断通过。

全部候选结论均为 **Untested（环境阻塞）**，不是对候选兼容性的否定。本批没有创建正式指南，也没有新增指南索引。

五项门槛汇总为：安装 30/30、精确发现 30/30、运行时加载与核心调用 0/30、第二环境与个人级端到端 0/20、回滚 30/30。

## 环境与隔离方法

| 项目 | 值 |
| --- | --- |
| CodeArts CLI | 26.8.1，真实二进制 `C:\Users\AI_BA\.codeartsdoer\installers\bin\codearts.exe` |
| 系统 | Windows 11 专业版 25H2，Build 26200 |
| Shell / 工具 | PowerShell 7.6.6；Git 2.53.0.windows.2；Node 24.14.1；npm 11.11.0 |
| 配置模型 | `mimo/mimo-v2.5`；真实端点当前返回不支持 |
| 固定版本 | Agentic Awesome `v20.0.0` / `6d4ea18320984083107f07ff69587fa355ee94c0` |

每个候选独立执行以下步骤：

1. 从已通过 tag/commit 校验的本地固定 checkout 复制候选目录到独立 vendor，再复制到 CodeArts 原生 `.codeartsdoer/skills/<name>`。没有携带上游 `skills/` 父目录层级到原生目标。
2. 项目 A、全新项目 B 分别使用自己的 `.codeartsdoer`；个人级使用 `C:\Users\AI_BA\.codeartsdoer\skills\<name>` 与可单独删除的 `C:\Users\AI_BA\.codeartsdoer\vendor\agentic-awesome-<name>`，consumer 中没有同名项目覆盖。
3. 对每份安装重新计算相对路径、字节数与 SHA-256，要求与候选自己的固定源 manifest 完全一致；同名 Skill 或 vendor 预存在时立即停止。
4. 运行 `codearts debug skill`，要求候选名与 `SKILL.md` 绝对路径唯一精确匹配。
5. 使用候选专属提示词运行真实 `codearts run -m mimo/mimo-v2.5 --format json`。断言必须包含来自预期目录的 completed Skill 事件和可观察结果；仅自然语言文本或退出码 0 不算通过。
6. 删除前核对目标绝对路径位于精确安装根内，只删除候选 Skill 与 vendor。随后再次运行诊断，要求旧路径零匹配。

## 环境阻塞证据

- 自动化进程没有真实 `CODEARTS_CLI_AK` / `CODEARTS_CLI_SK`；`codearts models` 因此显示认证失败。沿用既有外部 MiMo 配置的进程级非秘密占位值只用于到达已配置端点，没有被持久化。
- 独立模型探针与 30 次候选调用都收到同一上游错误：`400 Unsupported model mimo-v2.5`，目标为 MiMo chat-completions 端点。
- CodeArts 为这些错误返回进程退出码 0；每份 JSONL 都恰好只有一个 `type:error` 事件，30/30 份均没有 `tool` 字段、Skill call ID、MCP、Hook 或其他工具事件。
- 错误发生在候选内容调用之前，所以不能据此评价语义正确性、脚本、外部服务、Windows 运行时或个人级核心行为。占位值不能代替真实凭据，也不能授权改用华为云 MaaS 模型。

## 候选级代表调用

- `us-watchlist-alerts`：用合成 AAPL stop 请求检查上游三 Skill 前置、行情延迟、市场时段、本地状态和禁止交易边界。
- `animated-github-profile`：为虚构开发者设计三个 SVG、明暗主题、减少动画、XML 校验、ID 命名、缓存更新顺序和最小 Actions 权限。
- `launch-check`：在无 URL/owner/browser 授权时检查静态范围、owner-only 数据库门槛、浏览器风险、脱敏与评分限制。
- `second-deposit-igaming`：在无玩家导出与运营授权时检查本地隐私、字段映射、非因果限制、负责任博彩排除和国家规则门槛。
- `usage-engineer`：在无日志/会话授权时检查长日志摘要、重复失败、map 新鲜度、窄读和“只报告实测 token”规则。
- `watch-igaming`：在无媒体与依赖时检查安全临时目录、有界下载、字幕优先、场景抽帧、时间码、未观察区间和保留策略。
- `shopify-firebase-app`：在无版本/账户/凭据/云授权时检查 scaffold 与 deploy 前的 owner 决策、Secret、租户隔离、测试和资源清单门槛。
- `design-token-contrast`：以合成 CSS token pair 检查 WCAG 阈值、checker 抽取/不覆盖流程和“token 检查不等于页面认证”边界。
- `unpaid-intern`：在完整 kit 缺失时检查固定版本审查、Markdown workspace、事实标签、受限数据和 draft-only 外部动作停止规则。
- `goal-instruction-writer`：要求为十个只读文本文件生成包含 anchor、验收、验证、漂移、预算和终止条件的 Goal，但不执行该 Goal。

上述 30 次提示词都在 Skill 调用前被同一模型错误阻断，没有产生候选语义证据。

## 回滚与残留

- 30/30 个候选 Skill 目标和 30/30 个独立 vendor 目标已删除；30/30 次删除后诊断对旧绝对路径均为零匹配。
- 用户根 `package.json`、`codearts_cli.json`、持久权限文件的 SHA-256 前后分别保持 `589A2F93D6B401FCCE4EDED58C4C477C3891C3B580796862C58ACB4E5D73A4E7`、`6F08A23430F657E3CBF75ABDCF1CB7A08FE88504F6FDC51BA31B6530386E2E23`、`AC7831CD9D9FB18023BFD6C7778E71FF4A0DBCADAE60948189FBB0ECFDE2F447`。
- 十个个人级 Skill 与 vendor 路径最终全部不存在。`.tmp/v1027` 只保留 Git 忽略的本地证据，不进入提交。

## 正式指南决定

没有候选同时满足“安装成功、CodeArts 运行时确认加载、核心调用成功、全新环境复现、回滚成功”。因此本批不创建 `guides/` 内容，也不修改正式指南表。恢复真实可用模型后，必须从固定 Commit 重新执行候选专属调用；本批发现与回滚结果不能替代后续加载、语义、脚本或外部服务证据。
