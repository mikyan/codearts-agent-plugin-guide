# 2026-10-29: Ten Agentic Awesome v20.1.0 CodeArts validations

## Summary

This batch actually advanced ten previously uncovered Agentic Awesome content skills: `pypict-skill`, `concise-planning`, `avoid-ai-writing`, `meeting-notes`, `doc2math`, `seo-meta-optimizer`, `threat-modeling-expert`, `event-sourcing-architect`, `fable-safe-prompt`, and `full-output-enforcement`. The pinned version was `v20.1.0` / `ed953dd2928104238cd0b71d0789137e77e90cae`.

Every candidate independently received source-hash verification, exact CodeArts discovery, a real `codearts run`, precise removal, and post-removal discovery checks in project A, fresh project B, and user scope. Installation passed 30/30, discovery passed 30/30, and rollback passed 30/30. However, all 30 invocations received `400 Unsupported model mimo-v2.5` before any `skill` or other tool event. All ten results are therefore **Untested (environment blocked)**. This is not evidence that the candidates are incompatible, and none reached the formal-guide threshold. No `guides/` or guide-index entry was added.

The following complete process was repeated separately for every candidate; no event from one candidate stood in for another:

1. Project A: copy the pinned directory to `<A>/.codeartsdoer/skills/<candidate>`, compare every SHA-256, run `codearts debug skill`, run the candidate-specific `codearts run -m mimo/mimo-v2.5 --format json "<core assertion>"`, remove that exact directory, and run discovery again.
2. Project B: repeat from a new empty directory.
3. User scope: after confirming there was no same-named project skill, copy to `C:\Users\AI_BA\.codeartsdoer\skills\<candidate>` and repeat discovery, invocation, and removal from an independent clean directory. The user root manifest, model configuration, and persistent permissions were not modified.

Only non-secret placeholder AK/SK values were set in the process and were never persisted. Temporary permissions denied edit, write, delete, bash, read, glob, grep, webfetch, websearch, browser, and external-directory access.

## Rollback and guide decision

All 30 post-removal diagnostics excluded the former install location, and all ten user skill directories were absent. These non-secret file hashes matched before and after the batch:

- `package.json`: `589A2F93D6B401FCCE4EDED58C4C477C3891C3B580796862C58ACB4E5D73A4E7`
- `codearts_cli.json`: `6F08A23430F657E3CBF75ABDCF1CB7A08FE88504F6FDC51BA31B6530386E2E23`
- persistent permission file: `AC7831CD9D9FB18023BFD6C7778E71FF4A0DBCADAE60948189FBB0ECFDE2F447`

Because none of the ten passed runtime loading and core invocation, this run adds no formal guide or guide-table row. Once a real working `provider/model` is available again, all 30 candidate/scope invocations must be repeated. Discovery from this run cannot be upgraded into a compatibility claim.
