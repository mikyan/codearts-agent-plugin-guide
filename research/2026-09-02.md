## 环境与隔离

- 真实 CodeArts CLI 26.8.1：`%USERPROFILE%\.codeartsdoer\installers\codearts.cmd`。
- Windows 11 专业版 Build 26200；PowerShell 7.6.5；Git 2.53.0.windows.2；Node 24.14.1；npm 11.11.0。
- 模型：`mimo/mimo-v2.5`。进程环境原先没有 `CODEARTS_CLI_AK/SK`；测试只在子进程设置未持久化的非秘密占位值，让 CodeArts 26.8.1 进入已配置外部 Provider，实际模型鉴权仍由 Provider 配置完成。
- 每个候选均使用独立项目 A、独立项目 B 与个人级 consumer。项目级安装到 `<项目>/.codeartsdoer/skills/<name>`，源码克隆到 `<项目>/.codeartsdoer/vendor/pm-skills-<name>`；个人级使用相同的 `~/.codeartsdoer/skills/<name>` 与独立 `vendor/pm-skills-<name>` 布局。
- 每次安装先检查同名冲突，再从固定本地镜像做独立 sparse checkout，确认 HEAD 后只复制选定 Skill 目录。该镜像来自同一固定 GitHub Commit；没有把上游 `pm-*` 父目录带入原生 Skills 目标。
- 每个范围先用 `codearts debug skill` 断言准确绝对路径，再用 `codearts run -m mimo/mimo-v2.5 --format json` 调用。提示词禁止网络和文件写入，未使用 `--auto`。单次上限 90 秒；超时只终止准确的 CodeArts 子进程并记为失败。

## 逐项结果

1. **`brainstorm-ideas-new` — Partial：**项目 A/B 均只调用一次目标 Skill，并生成 PM、Designer、Engineer 各 5 项想法及 Top 5。个人级同样完成发现与加载，但在 90 秒上限没有最终文本，退出记为 124。个人级核心能力未复现，因此不发布指南。
2. **`prioritize-assumptions` — Works：**三范围均正确将 A/B/C/D 映射为测试、实施、拒绝、推迟，并为 A 设计完成日历授权的行为实验与 25% 阈值。个人级最初因没有输出 `TEST-FIRST=A` 的等号后缀被自动断言标为失败；原始文本表格明确显示 A → TEST-FIRST 等全部语义，故这是可审计的断言假阴性，不是重跑结果。
3. **`opportunity-solution-tree` — Works：**三范围都输出单一 7 日激活指标、至少 3 个机会、每个优先机会至少 3 个解决方案，以及带指标和阈值的实验。
4. **`product-vision` — Works：**三范围都生成 3 个一句话愿景、明确选择和价值对齐。项目 A 除目标 Skill 外出现 3 个 CodeArts 内部 `todowrite` 完成事件；它们只记录任务状态，没有网络或文件副作用，不影响核心门槛。
5. **`value-proposition` — Works：**三范围都覆盖 Who、Why、What Before、How、What After、Alternatives，并生成简短价值主张与定位。
6. **`lean-canvas` — Works：**三范围都覆盖九个 Lean Canvas 部分，并列出关键假设和验证实验。
7. **`swot-analysis` — Works：**三范围都输出四个象限各至少 3 项和至少 3 个优先行动；仅使用提示词给定事实。
8. **`porters-five-forces` — Works：**三范围都对五力评级，指出最关键的两项力量并评估行业吸引力；没有实时市场检索。
9. **`stakeholder-map` — Works：**三范围把四个给定角色放入正确象限，提供频率、渠道、信息、忽略风险和冲突对齐动作。
10. **`user-stories` — Works：**三范围都生成恰好 3 个故事，每项包含标题、As a/I want/so that、Design N/A、4 条验收标准与 INVEST 检查。自动断言要求字面量 `DESIGN=N/A`，而结果使用 `Design: N/A` 或中文标签；原始文本证明结构全部满足，因此人工审计纠正为通过。
