# 2026-09-25: Ten Agentic Awesome v18.4.0 Skills Tested on CodeArts CLI

[中文](2026-09-25.md)

## Batch conclusion

This batch advanced ten previously uncovered `SKILL.md` candidates pinned to `sickn33/agentic-awesome-skills` release `v18.4.0` and commit `7b534bc15d833baf3bc98b3ca4fb23eda48342bb`. Six were new in the release; four more came from the same pinned snapshot's weather-data and agent-memory themes.

Every candidate received an independent safety review, project A installation, fresh project B installation, user-scope installation from a directory without a project override, real CodeArts discovery, a representative invocation, and precise rollback. All 30 installed states were discovered by `codearts debug skill` at the exact absolute path. All 30 `codearts run` calls exited 0 with exactly one target `skill:completed` event. All 30 targets were removed precisely and disappeared from post-removal discovery.

After manual semantic review, only `weather-data-lifecycle-management` passed the main and remote-clone publication flows in two projects and user scope, including core semantics and rollback. It is **Works** and has a formal bilingual guide. The other nine are **Partial** or **Adapter Required**: they installed and loaded, but lacked a real download/backend operation, made calculation errors, invented inputs, produced cross-scope semantic failures, or lacked a CodeArts-native implementation.

## License and safety review

- Nine candidate directories contained only one `SKILL.md`; `agent-memory-discipline` also contained `references/entry-format.md`. Every pinned directory was read in full and received a file SHA-256 manifest.
- The directories contained no manifest, lockfile, install/preinstall/postinstall hook, executable script, binary, downloader, or candidate telemetry. No AWS, HTTP, database, dashboard, or installation example from the candidate text was run.
- Original AAS non-code content defaults to CC BY 4.0; code and tooling are MIT. More specific third-party notices take precedence. `agent-memory-discipline` is explicitly CC0-1.0, the original `memory-systems` repository is MIT, and the original HAM repository is MIT but says “Claude Code only.”
- All representative calls used inline synthetic data and a temporary permission file denying Write/Edit/Delete/Bash/Read/Web/Browser. No real weather data, cloud credential, memory backend, user session, production cache, or real deletion was accessed.
- Installation used only the pinned candidate directory, native `.codeartsdoer/skills/<name>`, and independently removable `vendor/agentic-awesome-<name>`. User-root `package.json`, `codearts_cli.json`, persistent permissions, and credentials were not changed.

## Installation, discovery, invocation, and rollback method

For every main-batch candidate, the pinned source directory was copied into a scope-local vendor and then into native Skills. Real `codearts debug skill` had to return exactly one matching `name + absolute SKILL.md path`. A candidate-specific `codearts run -m mimo/mimo-v2.5 --format json` preserved JSONL, call IDs, and final text for manual review. The full process was repeated from zero in project B and user scope. After validating the absolute deletion targets, only the exact Skill and vendor were removed, followed by a real discovery diagnostic.

The sole passing candidate also followed the exact guide flow: a fresh sparse clone of GitHub tag `v18.4.0` in each scope, full-commit verification, native copy, invocation, and rollback. `weather-data-reproducibility` entered the same publication check but was withdrawn when publication project A invented values.

One excluded harness failure occurred at the start of publication testing: a PowerShell function parameter conflicted with an automatic variable, so `codearts debug skill` received no arguments and entered the TUI. No candidate invocation completed in that temporary project. The parameter was fixed and the flow restarted from zero in a new directory; the failed harness run is not counted for any candidate.
