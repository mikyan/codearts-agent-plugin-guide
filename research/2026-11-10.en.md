# 2026-11-10: CodeArts verification of ten interface-design Skills

[中文](2026-11-10.md)

## Summary

This batch advanced ten previously uncovered candidates: `better-accessibility`, `better-colors`, `better-layout`, `better-typography`, `better-ui`, `break`, `build-design`, `explain-interface`, `state-machine`, and `variant`. The pinned source is Agentic Awesome `v20.7.0` / `9ffb3aafc57fb29951e3da281de6556c31570800`; its retained upstream source is `jakubkrehel/skills` commit `60bf140e43c98b248e6594487384ec967e89d98a`.

Every candidate independently completed fixed-source manifest comparison, unique CodeArts discovery, a real `codearts run` attempt, exact removal, and post-removal discovery in project A, a fresh project B, and user scope. Installation, discovery, and rollback passed 30/30. However, all 30 `huaweicloud-maas/GLM-5.1` calls displayed an IAM authentication failure before any `skill` or other tool event. Twenty-four then recorded `MessageAbortedError`; six retained the `APIG.0301` API error object. Loading and representative results were 0/30.

All ten are therefore **Untested (environment blocked)**, not known-incompatible. This run adds no `guides/` page or guide-index row.

The official documentation places project Skills at `<project>/.codeartsdoer/skills` and user Skills at `~/.codeartsdoer/skills`, with project scope taking priority for a same-named Skill. This batch created no same-name collision. User calls ran from independent directories without a project copy.

Each candidate independently followed this process:

1. Project A: copy the pinned directory to `.tmp/verification/2026-11-10-agent-skills/runs/<candidate>-a/.codeartsdoer/skills/<candidate>`, compare manifests, run discovery and the candidate-specific call, remove the exact target, then run post-removal discovery.
2. Project B: repeat from zero in a fresh work directory without reusing project A installation, call, or rollback evidence.
3. User scope: after checking for collision, copy to `C:\Users\AI_BA\.codeartsdoer\skills\<candidate>`, repeat discovery and invocation from an independent consumer directory, then remove the exact target.

User-scope testing did not change the user-root `package.json`, `codearts_cli.json`, or persistent permission file, and did not retain the upstream parent-directory hierarchy in the CodeArts destination.
