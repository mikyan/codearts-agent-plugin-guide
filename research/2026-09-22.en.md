## License and security review

- Each of the ten installed pinned directories contained exactly one `SKILL.md`: no manifest, lockfile, install/postinstall hook, binary, downloader, telemetry code, or runtime dependency. Installation copied only fixed files that had already been read and hashed.
- Every original candidate source declared MIT. Agentic Awesome code is MIT, while aggregated content follows `LICENSE-CONTENT` and the original source licenses.
- The bodies of `devops-pipeline-builder`, `api-integration-architect`, and `api-integration` include deployment, network, or credential examples. This run used synthetic read-only design prompts and denied Bash, file, network, browser, and external-directory permissions.
- The full `review-and-simplify-changes` workflow can use sub-agents and edit code. This run explicitly used a tiny `review-only` scope and did not start sub-agents, read Git, or edit files.
- The first publication harness omitted the CodeArts channel environment, so six calls failed before the model request with `Network request blocked`. They emitted no Skill event and were all rolled back. After adding the same process environment as the main run, publication flow restarted from zero in a new isolation root. The infrastructure failures were not treated as candidate pass evidence.

## Installation, discovery, invocation, and rollback method

The main run copied each pinned candidate to a scope-specific `vendor/agentic-awesome-<name>` and then to the native CodeArts `skills/<name>` directory. Every scope first ran real `codearts debug skill`, requiring exactly one match for the candidate name and absolute `SKILL.md` path. A candidate-specific `codearts run -m mimo/mimo-v2.5 --format json` then had to emit exactly one completed Skill event from the expected absolute path.

All 30 main installations, discoveries, loads, and invocations passed the technical assertions. The two candidates closest to publication were also run using the proposed published flow: clone from GitHub, sparse-checkout `skills/<name>`, checkout the fixed commit, copy into the native directory, and invoke the same test. All six publication-flow calls also emitted exactly one target Skill event.

Before deletion, each absolute target was checked to remain inside its intended `.codeartsdoer` root. Only the exact Skill and vendor directories were removed, followed by real `codearts debug skill` requiring zero matches for the former `name + location`.

## Scope limits
