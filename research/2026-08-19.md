CodeArts 官方文档支持项目级 `.codeartsdoer/skills` 与个人级 `~/.codeartsdoer/skills`，同名时项目级优先；插件也分别支持项目和个人目录。个人级在这里表示“当前用户的所有 CodeArts 项目可用”，不是整台机器所有用户共享。

## 验证环境

- Windows 11 Build 26200
- CodeArts CLI 26.8.1
- PowerShell 7.6.5
- Node.js 24.14.1、npm 11.11.0、Git 2.53.0
- 自定义模型：`mimo/mimo-v2.5`
- 凭据只由 CodeArts 进程继承，未输出或写入仓库
- 真实调用使用 `codearts run --format json --sandbox`，未使用 `--auto`

本轮没有验证 CodeArts 桌面端/IDE 和 Linux。

## 发现的问题

测试前，用户根 `%USERPROFILE%/.codeartsdoer/package.json` 已包含 CodeArts 自带的 `@opencode-ai/plugin@26.8.1`。如果直接把第三方依赖合并进这个文件，再在用户根安装，系统 npm 和 CodeArts 自动 Reify 都会尝试从公共 npm Registry 解析该内部版本并返回 `ETARGET`。

因此个人级适配不能直接复用项目级依赖清单。验证通过的结构是：

```text
~/.codeartsdoer/
  plugins/<project>.ts
  vendor/<project>/
    package.json
    package-lock.json
    node_modules/
  skills/<copied-skill>/
```

每个项目拥有独立的 `vendor` 清单。插件使用相对于 `~/.codeartsdoer/plugins` 的固定路径加载上游入口，Skills 则复制到 CodeArts 原生个人级目录。用户根 `package.json` 保持不变。

## Ponytail 实测

- `vendor/ponytail/package.json` 只固定 `@dietrichgebert/ponytail` 4.9.0。
- 使用 `npm install --ignore-scripts --no-audit --no-fund` 安装。
- `plugins/ponytail.ts` 加载上游 `.opencode/plugins/ponytail.mjs`。
- 6 个 Skill 目录复制到个人级 `skills`。
- 从一个没有项目 `.codeartsdoer` 的独立目录运行 CodeArts。
- `ponytail-help` 产生成功的原生 `skill` 工具事件，其基础目录位于个人级 Skills 路径，最终输出为：

```text
Lite, Full, Ultra
```

## Superpowers 实测

- `vendor/superpowers/package.json` 固定 Git Tag `v6.3.0`。
- 使用 `npm install --ignore-scripts --no-audit --no-fund` 安装。
- `plugins/superpowers.ts` 加载上游 `.opencode/plugins/superpowers.js`。
- 14 个 Skill 目录复制到个人级 `skills`。
- 从同一个无项目级配置的独立目录运行 CodeArts。
- `systematic-debugging` 产生成功的原生 `skill` 工具事件，其基础目录位于个人级 Skills 路径，最终输出为：

```text
NO FIXES WITHOUT ROOT CAUSE INVESTIGATION FIRST
```

## 回滚验证

Ponytail 和 Superpowers 的个人级插件、独立 `vendor` 目录与对应 Skill 目录均被完整移出用户 CodeArts 目录。随后确认：

- 两组第三方 Skills 不再被发现；
- 用户根 `package.json` 的 SHA-256 与测试前完全相同；
- `codearts_cli.json`、凭据和其他 CodeArts 插件没有被修改。

项目级安装此前已在两个隔离项目中分别复现并完成回滚。两个范围的安装与卸载步骤已经写入正式指南。
