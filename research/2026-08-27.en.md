- Environment-presence checks returned `CODEARTS_CLI_AK=False` and `CODEARTS_CLI_SK=False`. No credential was read, printed, copied, hashed, or fabricated.
- The [official CodeArts CLI Skills documentation](https://support.huaweicloud.com/usermanual-cli/codeartsagent_cli_0019.html), updated 2026-08-19, specifies project `.codeartsdoer/skills/<name>`, user `~/.codeartsdoer/skills/<name>`, project priority for same-name Skills, and a `name` matching the target directory. This run used those native paths and did not reproduce upstream parent-directory depth in CodeArts targets.
- Each of the eight executable candidates used `.tmp/verification/2026-08-27-1600/scopes/<skill>/project-a`, a fresh `project-b`, and a `user-consumer` with no same-name project copy. User targets were `~/.codeartsdoer/skills/<skill>`.
- Every scope checked collision absence, copied the complete candidate directory at the pinned commit, compared `SKILL.md` SHA-256, ran `codearts debug skill` and a candidate-specific `codearts run -m mimo/mimo-v2.5 <prompt>`, removed the exact absolute target, and ran discovery diagnostics again.
- All 24 installed-state diagnostics, 24 core invocations, and 24 post-removal diagnostics returned “authentication failed, environment variables CODEARTS_CLI_AK/CODEARTS_CLI_SK are not set.” CodeArts CLI 26.8.1 still returned exit code `0` for this failure. The error text, not exit status, is therefore the failure assertion; exit code 0 is not treated as load or invocation success.
