## 环境与隔离方法

| 项目 | 值 |
| --- | --- |
| CodeArts CLI | 26.8.1，真实二进制 `~/.codeartsdoer/installers/bin/codearts.exe` |
| 系统 | Windows 11 25H2，Build 26200 |
| Shell / 工具 | PowerShell 7.6.6；Git 2.53.0.windows.2；Node 24.14.1；npm 11.11.0 |
| 配置模型 | `mimo/mimo-v2.5`；真实端点当前返回不支持 |
| 固定版本 | Agentic Awesome `v19.13.0` / `2fa03dc172ad6ea88caca9c51edd1a28d642b396` |

每个候选独立执行以下步骤：

1. 在项目 A、全新项目 B 和个人级 consumer 分别执行 `git clone --depth 1 --filter=blob:none --sparse --branch v19.13.0`，再设置 `skills/<name>` sparse checkout，并核对完整 Commit。
2. 项目级复制到 `<项目>/.codeartsdoer/skills/<name>`，vendor 为 `<项目>/.codeartsdoer/vendor/agentic-awesome-<name>`；个人级使用 `~/.codeartsdoer/skills/<name>` 与 `~/.codeartsdoer/vendor/agentic-awesome-<name>`。同名冲突会立即停止。
3. 运行 `codearts debug skill`，要求候选名和 `SKILL.md` 的绝对路径都唯一精确匹配。
4. 使用真实 `codearts run -m mimo/mimo-v2.5 --format json` 发起候选专属代表调用。临时权限配置拒绝 shell、文件读写、浏览器、网络和外部目录工具；进程级非秘密占位 AK/SK 没有写入磁盘。
5. 删除前再次确认两个目标都位于精确安装根下，只删除候选 Skill 和 vendor；随后运行删除后 `codearts debug skill`，要求旧绝对路径零匹配。

## 环境阻塞证据

- `codearts models` 仍列出 `mimo/mimo-v2.5`、`mimo/mimo-v2.5-pro`、`huaweicloud-maas/GLM-5.1` 和 `GLM-5.2`。
- `mimo/mimo-v2.5` 的 30 次候选调用都返回同一上游 `400`：`Unsupported model mimo-v2.5`。CodeArts 进程退出码仍为 0，因此本批以 JSON 错误正文和“零工具事件”为失败断言，不能把退出码 0 当成功。
- 独立 `mimo/mimo-v2.5-pro` 探针也返回 `400 Unsupported model mimo-v2.5-pro`。
- 独立 `huaweicloud-maas/GLM-5.2` 探针使用非秘密占位值时返回 `401 Incorrect IAM authentication information`。自动化进程没有真实 `CODEARTS_CLI_AK` / `CODEARTS_CLI_SK`，因此不能切换到华为云模型完成调用。
- 这些错误都发生在任何 Skill 事件之前。候选内容没有机会被运行时调用，故不得给出 `Works`、`Partial` 或正式指南。
