## 结论摘要

本批实际推进了 10 个此前未覆盖的 Agentic Awesome 内容型 Skill：`pypict-skill`、`concise-planning`、`avoid-ai-writing`、`meeting-notes`、`doc2math`、`seo-meta-optimizer`、`threat-modeling-expert`、`event-sourcing-architect`、`fable-safe-prompt` 和 `full-output-enforcement`。固定版本为 `v20.1.0` / `ed953dd2928104238cd0b71d0789137e77e90cae`。

每个候选都独立完成了项目 A、全新项目 B、个人级三个范围的源文件哈希比对、CodeArts 唯一发现、真实 `codearts run`、精确卸载和卸载后发现检查。30/30 次安装、30/30 次发现和 30/30 次回滚通过；但 30/30 次调用都在产生任何 `skill` 或其他工具事件之前收到 `400 Unsupported model mimo-v2.5`。因此十项全部记为 **Untested（环境阻塞）**，不能据此判断候选不兼容，也没有任何候选达到正式指南门槛。本轮不新增 `guides/` 或指南索引。

## 环境与隔离方法

| 项目 | 值 |
| --- | --- |
| CodeArts CLI | 26.8.1；真实二进制 `C:\Users\AI_BA\.codeartsdoer\installers\bin\codearts.exe` |
| 系统 | Windows 11 Pro 25H2，Build 26200.9711 |
| Shell / 工具 | PowerShell 7.6.6；Git 2.53.0.windows.2；Node 24.14.1；npm 11.11.0 |
| 配置模型 | `mimo/mimo-v2.5` |
| 固定来源 | Agentic Awesome `v20.1.0` / `ed953dd2928104238cd0b71d0789137e77e90cae` |

每个候选分别执行以下完整流程，未用一个候选的事件替代另一个候选：

1. 项目 A：复制固定目录到 `<A>/.codeartsdoer/skills/<候选>`，逐文件比对 SHA-256，运行 `codearts debug skill`，运行候选专用 `codearts run -m mimo/mimo-v2.5 --format json "<核心断言>"`，删除该精确目录，再次运行发现检查。
2. 项目 B：从新的空目录重复同一流程。
3. 个人级：确认不存在同名项目级 Skill 后，复制到 `C:\Users\AI_BA\.codeartsdoer\skills\<候选>`，从独立干净目录重复发现、调用和卸载；没有修改用户根清单、模型配置或持久权限。

进程只设置了非秘密占位 AK/SK，未持久化。临时权限拒绝 edit、write、delete、bash、read、glob、grep、webfetch、websearch、browser 和外部目录访问。
