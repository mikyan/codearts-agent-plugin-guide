# 2026-10-15: Ten Agentic Awesome v19.7.0 CodeArts validations

[简体中文](2026-10-15.md)

## Executive result

This batch advanced ten previously uncovered candidates. Every candidate was installed independently in project A, a fresh project B, and a user-scope consumer with no same-name project override. All 30 installations were exactly discovered by `codearts debug skill` and emitted a completed Skill event from the intended absolute path. All 30 precise rollbacks passed.

Only `cockney` passed installation, loading, representative capability, second-environment reproduction, user-scope reproduction, and rollback, so it received a formal bilingual guide. The other nine remain research-only because of missing browser/simulator/MCP core capabilities, a timeout, post-verification edits without another check, semantic drift, or a genuinely failing test.

## Environment and isolation

| Item | Value |
| --- | --- |
| CodeArts CLI | 26.8.1, real `~/.codeartsdoer/installers/bin/codearts.exe` binary |
| OS | Windows 11, build 26200 |
| Shell / Git | PowerShell 7.6.6; Git 2.53.0.windows.2 |
| Runtime | Node 24.14.1; npm 11.11.0 |
| Model | `mimo/mimo-v2.5` |
| Credential boundary | Non-secret placeholder AK/SK values existed only in child processes to use the already configured external model; credentials were never persisted, printed, or hashed |

Each candidate followed the same independent final process:

1. In project A, project B, or the user consumer, run `git clone --depth 1 --filter=blob:none --sparse --branch v19.7.0`, then `sparse-checkout set skills/<name>`, and require the exact pinned HEAD every time.
2. Project vendor and native targets were `<project>/.codeartsdoer/vendor/agentic-awesome-<name>` and `<project>/.codeartsdoer/skills/<name>`. User targets were the matching paths under `~/.codeartsdoer`; the invocation directory had no project override.
3. These are content Skills, so only the pinned Skill directory was copied into CodeArts native Skills. No npm/pip installation, lifecycle script, binary, or unaudited download ran.
4. Write-capable candidates used a workspace-local `KERNEL_DATA_DIR` that allowed only local Read/Glob/Grep/Write/Edit/Bash and denied browser, network, external directory, and deletion access. Text-only candidates denied every non-Skill tool. Persistent permissions were untouched.
5. After `codearts debug skill`, `codearts run -m mimo/mimo-v2.5 --format json` invoked a representative capability. Write-capable synthetic fixtures used `--auto`.
6. Rollback first resolved the exact absolute targets inside the intended root, removed only the candidate Skill and vendor, and reran discovery to require the former path to be absent.
