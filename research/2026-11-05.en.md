## Summary

This batch advanced ten candidates not previously covered under these slugs: `bowmark`, `coupler-marketing-analytics`, `figma-designer`, `landing-page-design`, `nano-settlement-verify`, `sequenzy-email-marketing`, `stageshow`, `mobbin`, `slideshow`, and `sfxmint`. The pinned aggregate source is Agentic Awesome `v20.5.0` at `22fc684f5f0229123b8177eca58eb4b0f07db941`.

Each candidate independently completed source-manifest comparison, unique CodeArts discovery, a real `codearts run`, precise removal, and post-removal discovery in project A, a fresh project B, and user scope: 30/30 installations, 30/30 discoveries, and 30/30 rollbacks passed. However, all 30 `mimo/mimo-v2.5` calls returned `400 Unsupported model mimo-v2.5` before any `skill` or other tool event. An independent `mimo/mimo-v2.5-pro` probe likewise returned `400 Unsupported model mimo-v2.5-pro`.

All ten results are therefore **Untested (environment blocked)**, not incompatibility findings. No `guides/` entry or guide index row was added.

The official documentation places project Skills in `<project>/.codeartsdoer/skills` and user Skills in `~/.codeartsdoer/skills`, with project scope taking priority for same-named Skills. Earlier evidence in this repository observed CodeArts 26.8.1 resolving the user path instead, so this batch created no same-name collision and does not treat the documented priority as fresh runtime proof. User calls ran from independent workspaces with no same-named project directory.

For each candidate independently:

1. Project A: copy the pinned candidate into `<A>/.codeartsdoer/skills/<candidate>`, compare every SHA-256, run `codearts debug skill` and a candidate-specific `codearts run -m mimo/mimo-v2.5 --format json ...`, remove the exact directory, and run post-removal discovery.
2. Project B: repeat the entire process from an empty workspace without reusing project A installation, invocation, or rollback evidence.
3. User scope: after confirming no same-named project override, copy into `C:\Users\AI_BA\.codeartsdoer\skills\<candidate>`, then repeat discovery, invocation, exact removal, and post-removal discovery from an independent directory.

User testing did not change the user-root `package.json`, `codearts_cli.json`, or persistent permission file. Temporary runtime policy explicitly denied edits, writes, deletion, Shell, reads, glob, grep, web, browser, and external directories. A `skill` event could still be observed, but every request failed before any event in this batch.

No candidate passed all five gates of actual installation, CodeArts loading, representative invocation, clean second-environment reproduction, and rollback, so no formal guide was created.
