# 2026-10-26: Ten CodeArts validations from Agentic Awesome v20.0.0

[中文](2026-10-26.md)

## Summary

This batch advanced ten previously uncovered `SKILL.md` candidates. Every candidate was installed independently in project A, a fresh project B, and a user-scope consumer with no same-named project override. All 30 installed copies matched the pinned source file-for-file by relative path, byte count, and SHA-256; all 30 `codearts debug skill` runs discovered exactly one candidate at the intended absolute path.

All 30 real `codearts run -m mimo/mimo-v2.5 --format json` attempts received upstream `400 Unsupported model mimo-v2.5` before any Skill or other tool event. CodeArts still exited 0, so the assertions used the JSON error body and zero tool events; discovery cannot be reported as runtime loading. All 30 exact rollbacks and post-removal diagnostics passed.

Every result is **Untested (environment blocked)**, not an incompatibility finding. This batch created no formal guide and no guide-index entry.

Every candidate independently followed these steps:

1. Copy the candidate directory from a local pinned checkout whose tag and full commit were verified into an independent vendor directory, then into the native CodeArts `.codeartsdoer/skills/<name>` destination. The upstream `skills/` parent hierarchy was not carried into the native destination.
2. Project A and fresh project B used separate `.codeartsdoer` roots. User scope used `~/.codeartsdoer/skills/<name>` plus independently removable `~/.codeartsdoer/vendor/agentic-awesome-<name>` from a consumer with no project override.
3. Recompute relative paths, sizes, and SHA-256 for every installed file and require an exact match with the pinned source manifest. Any pre-existing same-named Skill or vendor would stop the run.
4. Run `codearts debug skill` and require one exact name plus absolute `SKILL.md` path match.
5. Run a candidate-specific real `codearts run -m mimo/mimo-v2.5 --format json`. Passing requires a completed Skill event from the expected directory and an observable result; plausible prose or exit code 0 does not pass.
6. Validate each removal target as a child of the exact installation root, remove only the candidate Skill and vendor, then rerun diagnostics and require zero old-path matches.

## Environment-blocker evidence

- `codearts models` still listed `mimo/mimo-v2.5`, `mimo/mimo-v2.5-pro`, `huaweicloud-maas/GLM-5.1`, and `GLM-5.2`.
- A separate channel probe and all 30 candidate calls received the same upstream error: `400 Unsupported model mimo-v2.5` from the MiMo chat-completions endpoint.
- CodeArts exited 0 for those errors. The JSON body was `type:error`, with no `skill`, MCP, Hook, or other tool event.
- The automation process had no real `CODEARTS_CLI_AK` / `CODEARTS_CLI_SK`, so it could not switch to Huawei Cloud MaaS. Placeholder values cannot substitute for credentials and were not persisted.
- The error occurred before candidate content was invoked. It provides no semantic, external-service, or Windows-runtime compatibility evidence.

## Candidate-specific representative calls

- `product-design-harness`: review a reversible help-panel pilot backed only by one stakeholder opinion, requiring three flow verdicts, evidence tier, boundaries, and the next human decision.
- `a4a`: with no SDK, identity, relay, or recipient authorization, enumerate read-only capability checks and stop conditions.
- `cooper-email`: with no account, key, recipient, or send authorization, cover one-time-secret handling, idempotency, finite waits, and OTP boundaries.
- `faber-language`: with no compiler, distinguish `check` from `run`, explain core spelling, and avoid claiming validation.
- `doomsday-escrow`: with no verifier or chain evidence, enumerate pinned-source review and independent evidence fields without classifying a real bounty.
- `datawebot`: with no MCP, sign-in, or spending approval, explain discover-first behavior, Job approval, idempotent retry, and bounded polling.
- `footval-follow-matches-and-tables`: explain offline tool selection, UTC, and freshness limits without inventing scores.
- `footval-scout-and-rank-players`: translate “left-footed centre-backs under 23 in Serie A below EUR 30M” into exact filter boundaries without naming players.
- `footval-stats-and-transfer-news`: explain parameters and reliability boundaries for a Champions League scoring table and Galatasaray rumors without inventing results.
- `footval-value-and-compare-players`: explain FootVal value, market value, the ±5% fair band, and factors without valuing a real player.

The same model error stopped all 30 prompts before Skill invocation, so none produced candidate-semantic evidence.
