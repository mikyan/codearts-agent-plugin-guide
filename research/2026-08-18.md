## 安全检查

- Ponytail 4.9.0 从固定的 npm Release 安装。该版本没有 install/postinstall 生命周期脚本。验证时观察到的 npm Integrity 为 `sha512-OSdybtBZ3uDd5m/+zyz4h8/+BVBR9nGFhqTDmQkQb1v7k4Vfc1qql78naY64UjocdBPqR94htZEkKu2wpKTJaw==`。
- Superpowers 6.3.0 没有发布为 npm Registry 包，因此从固定 Git Tag 安装。该版本没有依赖或生命周期脚本。
- 两个项目均在隔离项目目录中使用 `npm install --ignore-scripts --no-audit --no-fund` 安装。
- 没有修改用户全局 CodeArts 配置。Ponytail 模式命令会在用户的 OpenCode 配置目录写入状态，因此本轮刻意没有调用。

## 兼容性发现

1. 两个上游依赖均在各自两个独立项目目录中成功安装。
2. CodeArts 没有扫描以 `.mjs` 结尾的项目插件入口；等价的 `.js` 包装入口可以加载。
3. 仅使用 `.js` 包装入口时，`codearts debug skill` 能显示插件通过 `config.skills.paths` Hook 加入的上游 Skills。
4. 真实 `codearts run` 会话的 `skill` 工具仍然只包含 CodeArts 系统 Skills，无法调用这些动态路径中的上游 Skills。
5. 把上游 Skill 目录复制到 CodeArts 原生项目路径 `.codeartsdoer/skills` 后，运行时发现恢复正常。插件包装入口继续负责上游 Hooks，以及 Ponytail 的命令注册。
6. 两个候选项目都在第二个独立项目中用同样结构复现成功。
7. 临时移走完整项目 `.codeartsdoer` 后，第三方 Skills 从发现结果中消失；恢复目录后安装随之恢复，确认了项目级回滚边界。

因此，在 CodeArts CLI 26.8.1 中必须使用适配器：`.js` 插件入口加一份项目级上游 Skills 副本。

## 真实模型调用

Ponytail 测试提示词：

```text
Call the skill tool exactly once with name ponytail-help. Do not use glob, read, or shell tools. After the skill tool returns, output the three level names in the same order as its Levels table.
```

两个隔离项目均产生了成功的 `ponytail-help` 工具调用，并返回：

```text
Lite, Full, Ultra
```

Superpowers 测试提示词：

```text
Call the skill tool exactly once with name systematic-debugging. Do not use glob, read, or shell tools. After the skill tool returns, output only its Iron Law sentence.
```

两个隔离项目均产生了成功的 `systematic-debugging` 工具调用，并返回：

```text
NO FIXES WITHOUT ROOT CAUSE INVESTIGATION FIRST
```
