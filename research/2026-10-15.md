## 环境与隔离方法

| 项目 | 值 |
| --- | --- |
| CodeArts CLI | 26.8.1，真实二进制 `~/.codeartsdoer/installers/bin/codearts.exe` |
| 系统 | Windows 11，Build 26200 |
| Shell / Git | PowerShell 7.6.6；Git 2.53.0.windows.2 |
| 运行时 | Node 24.14.1；npm 11.11.0 |
| 模型 | `mimo/mimo-v2.5` |
| 凭据边界 | 仅向子进程注入非秘密占位 AK/SK 以使用已有外部模型配置；从未持久化、打印或哈希凭据 |

每个候选都采用相同但独立的最终流程：

1. 在项目 A、项目 B 或个人级 consumer 的独立工作目录中，执行 `git clone --depth 1 --filter=blob:none --sparse --branch v19.7.0`，再执行 `sparse-checkout set skills/<name>`；每次确认 HEAD 精确为固定 Commit。
2. 项目级 vendor 为 `<项目>/.codeartsdoer/vendor/agentic-awesome-<name>`，原生 Skill 为 `<项目>/.codeartsdoer/skills/<name>`。个人级使用 `~/.codeartsdoer/vendor/...` 与 `~/.codeartsdoer/skills/...`，调用目录没有项目级同名 Skill。
3. 候选均为内容型 Skill，优先复制到 CodeArts 原生 Skills 目录。没有运行 npm/pip 安装、生命周期脚本、二进制或未审查下载。
4. 写入型候选使用每工作区独立 `KERNEL_DATA_DIR`：只允许本地 Read/Glob/Grep/Write/Edit/Bash，拒绝浏览器、网络、外部目录与删除；纯文本候选拒绝所有非 Skill 工具。没有修改持久用户权限。
5. 安装后运行 `codearts debug skill`，再用 `codearts run -m mimo/mimo-v2.5 --format json` 调用代表能力。写入型候选使用 `--auto`，只作用于合成夹具。
6. 删除前验证绝对路径位于精确安装根，只删除候选 Skill 与 vendor；再运行诊断确认旧绝对路径消失。
